            How this advice is made
            1. Understand: Claude (or built-in rules without a key) reads the goal and writes test cases. You can check and edit both; disagreements with the rules are flagged for you to confirm.
            2. Measure: every model answers every test case. Accuracy, hallucinations, latency and tokens come from those runs.
            3. Match patterns: only architectures whose published best-practice conditions fit the task are considered; the rest are listed with the reason.
            4. Rank: designs that meet every requirement first, then accuracy 35%, cost 25%, speed 15% (0% for background jobs), simplicity 25%. No LLM writes the recommendation.

            Evidence labels: measured directly on your cases · from measurements replayed per case (e.g. which answers a cascade would escalate) · estimated for steps that need your systems (tools, retrieval, multi-agent turns).
