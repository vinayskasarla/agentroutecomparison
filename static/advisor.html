                  How this advice is made

                  1. Understand: Claude (or built-in rules without a key) reads the goal and writes test cases. You can check and edit both; disagreements with the rules are flagged.
                  2. Measure: every model answers every test case — live where this server has access, simulated elsewhere (each row says which).
                  3. Match patterns: only architectures whose published best-practice conditions fit the task are considered.
                  4. Rank architectures: designs meeting every requirement first, then accuracy 35%, cost 25%, speed 15% (0% for background jobs), simplicity 25%.
                  5. Pick models: every model is priced inside architecture 1. Best model = cheapest one that meets every requirement, preferring verified prices. Fallback = cheapest qualifying model on a different platform (and maker where possible), so one outage can't take both down.

                  No LLM writes the recommendation. Cost per 1,000 correct answers = cost per request ÷ accuracy × 1,000: the efficiency figure to compare models.
